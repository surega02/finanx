# Penyesuaian UI mobile — 26 Oktober 2026

## Persetujuan dan batas perubahan

Pengguna mengonfirmasi https://finanx-me.vercel.app/ sebagai Production dan meminta tiga penyesuaian setelah deployment:

1. Menghilangkan filter bulan/tahun tambahan pada Dashboard. Judul periode, tombol bulan sebelumnya/berikutnya, dan Hari Ini dipertahankan.
2. Menggabungkan Catat Lagi, Ubah, dan Hapus dalam satu menu titik tiga di setiap transaksi.
3. Menempatkan Simpan saldo awal dan Reset saldo awal berdampingan, termasuk pada mobile.

Poin pertama merupakan perubahan yang disetujui pengguna terhadap pemilih periode langsung yang sebelumnya ditentukan V2. Dokumen kanonis V1/V2 tidak diubah diam-diam; catatan ini merekam keputusan terbaru. Filter bulan/tahun histori transaksi tetap tersedia.

## Implementasi

- Menu transaksi memakai ikon yang sudah tersedia dan label ID/EN. Target sentuh minimum 44px; menu ditempatkan di dalam viewport menggunakan portal. Arrow Up/Down, Home/End, Escape, Tab, klik di luar, resize, dan scroll ditangani. Pemilihan aksi mengembalikan fokus ke pemicu sebelum membuka dialog.
- Daftar mobile menempatkan tanggal dan pemicu aksi dalam satu baris di bawah kategori/nominal. Nominal tidak dipotong.
- Tombol saldo awal memakai dua kolom dengan teks yang dapat membungkus. Validasi, konfirmasi update/reset, dan status penyimpanan tetap memakai implementasi sebelumnya.
- Token warna, tipografi, stamp, garis, dan material The Stamped Register dipertahankan. Tidak ada perubahan store, autentikasi, RLS, skema, atau migrasi database.

## Verifikasi dan deployment

`npm test`: 25/25 lulus. `npm run build`: lulus. Detector pada komponen yang berubah dan stylesheet: tidak ada finding.

Browser memakai build demo terisolasi dengan data sintetis pada Chrome desktop 1440px dan emulasi mobile 360px. Pengujian mencakup navigasi periode tanpa picker tambahan, menu tiga aksi, keyboard/fokus/dismissal, batas viewport, target sentuh, Catat Lagi satu insert, edit, hapus/urungkan, ekspor, kategori V1, saldo awal, pembatalan reset, tombol sejajar, dan lokalisasi.

Benchmark memakai 10.000 transaksi, 100 kategori, lima tahun histori. Pengukuran awal lulus desktop tetapi melewati beberapa ambang pada proksi CPU 4×: Dashboard render P95 1726 ms (batas 500), histori 574 ms (500), picker computation 498 ms (300), dan prefill 772 ms (300). Penyebab variasi belum dipastikan; Pengukuran ulang juga belum lulus: Dashboard render P95 1398 ms (batas 500), picker computation 338 ms (300), picker open 403 ms (300), dan prefill 545 ms (300). Histori render ulang 343 ms memenuhi batas 500 ms. Desktop ulang memenuhi seluruh batas (Dashboard render 36 ms, histori 32 ms, picker open 32 ms, prefill 35 ms). Tidak ada ambang yang dilonggarkan; hasil CPU 4× tetap menjadi temuan terbuka sebelum mengklaim kelulusan performa mobile. Proksi ini tidak membuktikan performa Android fisik.

Perubahan UI ini belum dideploy oleh agent. Pemeriksaan login, persistensi, isolasi dua akun, dan CSV pada URL Production serta Android fisik/Excel/Sheets tetap perlu dilakukan pada environment/perangkat terkait.

Hasil benchmark ulang: `mobile-ui-benchmark-20261026.json`. Hasil fungsi/tata letak setelah koreksi review: `mobile-ui-browser-20261026.json`, 63/63 pemeriksaan lulus, tidak ada uncaught browser error. Hasil ini disimpan terpisah agar tidak menimpa bukti benchmark gagal.

Review visual independen awal meminta satu koreksi material: bayangan keras menu diganti token overlay `--shadow-soft`.
